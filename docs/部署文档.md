# 部署文档

> 本文说明如何从源码构建、签名并安装「健身日程」App。

## 1. 产物与变体


| 变体      | applicationId         | 说明                                             | 产物路径                                            |
| ------- | --------------------- | ---------------------------------------------- | ----------------------------------------------- |
| debug   | `com.fitplan.app.dev` | 带 `.dev` 后缀，`versionName` 追加 `-<commit 数>`，不混淆 | `app/build/outputs/apk/debug/app-debug.apk`     |
| release | `com.fitplan.app`     | 开启 R8 混淆与资源压缩，`isProfileable`                  | `app/build/outputs/apk/release/app-release.apk` |


- `versionCode = 1`、`versionName = "0.1.0"`，硬编码在 `app/build.gradle.kts` 中，发版前手动修改。
- 两个变体共用同一个名为 `debug` 的 signingConfig（见第 4 节），所以默认情况下 **release 也用 debug 签名**，只适合内部分发；上架/正式分发必须配置自己的 keystore。
- 打包时会把 `COMMIT_COUNT`、`COMMIT_SHA`、`BUILD_TIME` 注入 `BuildConfig`，其中 release 的 `BUILD_TIME` 取最近一次 git 提交时间。



## 2. 环境准备

1. **JDK 21**（CI 使用 temurin 21）。
2. **Android SDK**：compileSdk 37.1、targetSdk 36、minSdk 26。
3. **Git 加入 PATH**：构建脚本会调用 `git rev-list`、`git rev-parse`、`git log` 生成版本信息，缺失会导致配置阶段报错。
4. 首次在 IDE 外构建时，确认仓库根目录存在 `local.properties`，内容形如：
  ```properties
   sdk.dir=C\:\\Users\\<用户名>\\AppData\\Local\\Android\\Sdk
  ```
   `local.properties` 已被 `.gitignore` 忽略，不要提交。



## 3. 构建 Debug APK

Windows：

```powershell
.\gradlew.bat clean assembleDebug
```

macOS / Linux：

```bash
./gradlew clean assembleDebug
```

产物：`app/build/outputs/apk/debug/app-debug.apk`。

## 4. Release 构建与签名

`app/build.gradle.kts` 的签名逻辑：若仓库根目录存在 `keystore.properties`，则用其中的字段**覆盖名为** `debug` **的 signingConfig**；release 直接复用这个 signingConfig。因此配置 keystore 后，debug 与 release 都由该 keystore 签名。

在仓库根目录新建 `keystore.properties`（已在 `.gitignore` 中，不会提交）：

```properties
storeFile=/absolute/path/to/your.keystore
storePassword=你的store密码
keyAlias=你的key别名
keyPassword=你的key密码
```

> `storeFile` 按 `file(...)` 解析，建议写绝对路径。

然后构建：

```bash
./gradlew clean assembleRelease
```

产物：`app/build/outputs/apk/release/app-release.apk`。

**没有** `keystore.properties` 时，release 会退回 Android 默认的 debug keystore 签名，无法用于正式发布。

## 5. 安装到设备



### 5.1 通过 Gradle（推荐，自动构建并安装 debug）

```bash
./gradlew :app:installDebug
```



### 5.2 通过 adb

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
```

安装 release 包：

```bash
adb install -r app/build/outputs/apk/release/app-release.apk
```

> debug 与 release 的 applicationId 不同（`.dev` 后缀），可以共存安装，各自拥有独立数据。



## 6. CI 自动构建

`.github/workflows/build.yml`：

- 触发：PR（忽略 `**.md` 改动）与 push 到 `main`。
- 步骤：`spotlessCheck` → `testDebugUnitTest` → `verifySqlDelightMigration` → `assembleDebug`。
- 产物：名为 `app-debug-<sha>` 的 artifact，内含 `app-debug.apk`；测试失败时上传测试报告。

从 GitHub Actions 对应 run 的 Artifacts 区域即可下载 APK，解压后安装。

## 7. 数据存储与备份

- 应用为纯本地离线应用，无网络权限。
- 主数据库：`fitplan.db`，位于应用私有目录（设备上的 `/data/data/<applicationId>/databases/`），普通用户无法直接访问。
- `AndroidManifest.xml` 中 `android:allowBackup="true"`，因此会参与系统自动备份/换机恢复（受系统与厂商策略影响）。
- debug 与 release 的包名不同，数据互不相通；从 debug 切到 release 相当于全新安装。



## 8. 卸载与数据清理

```bash
# 卸载（保留数据）
adb uninstall <applicationId>

# 清空应用数据（恢复到首次启动状态，会重新导入种子动作）
adb shell pm clear <applicationId>
```

- `com.fitplan.app.dev` 为 debug 包名，`com.fitplan.app` 为 release 包名。
- 清除数据或重装后，首次启动会从 `assets/exercises.json` 重新导入 60 条内置动作。



## 9. 常见问题


| 现象                        | 原因 / 处理                                                         |
| ------------------------- | --------------------------------------------------------------- |
| 配置阶段报 `git` 相关错误          | Git 未安装或不在 PATH；装上 Git 即可                                       |
| 提示找不到 Android SDK         | 缺少/错误的 `local.properties`，或未安装对应 SDK 平台                         |
| `spotlessCheck` 失败        | 本地先跑 `./gradlew spotlessApply` 再提交                              |
| release 包安装后与 debug 数据不一致 | 两者 applicationId 不同，属正常现象                                       |
| 想上架 / 正式分发                | 必须配置自己的 `keystore.properties`，并把 `versionCode`/`versionName` 递增 |
